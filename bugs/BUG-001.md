# BUG-001 — Transactions are not persisted after refresh

**Severity:** Medium
**Priority:** High
**Status:** Open
**Area:** Transaction Management / Data Persistence

## Description

New transactions added through the dashboard appear successfully in the transaction list and update the displayed totals, but the new data is not persisted.

After refreshing the application and logging in again, the newly added transaction is no longer present and the original transaction totals are restored.

## Preconditions

User is logged in and on the FinTrack dashboard.

## Steps to reproduce

1. Log in using the demo credentials.
2. Add a new transaction, for example:

   * Description: `Groceries`
   * Amount: `5000`
   * Type: `Expense`
   * Category: `Food`
3. Confirm that the transaction appears in the transaction list.
4. Confirm that the dashboard totals update.
5. Refresh the page.
6. Log in again.
7. Review the transaction list and dashboard totals.

## Expected result

The newly added transaction should remain available after refreshing and logging in again, and the dashboard totals should remain updated.

## Actual result

The newly added transaction disappears after refresh/re-login, and the original transaction list and totals are restored.

## Additional evidence

* No transaction API request was observed when a new transaction was added.
* `GET /api/transactions` continued to return only the original transaction records.
* The issue was reproduced during manual testing.

## Recommendation

Persist newly created transactions through a backend API/database or other persistent storage mechanism rather than keeping the new transaction only in the client-side state.
